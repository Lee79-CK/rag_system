# 장애대응매뉴얼 (Cloud 운영팀)

## 1. 목적
본 매뉴얼은 Private Cloud 플랫폼에서 발생하는 장애를 등급별로 분류하고, 등급에 따른 보고·대응·복구 절차를 정의한다.

## 2. 장애 등급 정의
| 등급 | 정의 | 예시 | 최초 보고 시한 |
|---|---|---|---|
| 1등급 (Critical) | 전사 서비스 중단 또는 데이터 유실 위험 | 컨트롤플레인 전면 장애, 스토리지 클러스터 다운 | 10분 이내 |
| 2등급 (Major) | 주요 서비스 일부 중단, 우회 불가 | 특정 AZ 네트워크 단절, DB 프라이머리 장애 | 30분 이내 |
| 3등급 (Minor) | 성능 저하 또는 일부 기능 제한, 우회 가능 | 노드 1대 NotReady, 배치 지연 | 2시간 이내 |
| 4등급 (Low) | 사용자 영향 없음, 모니터링 경보 | 디스크 사용률 80% 경보 | 익일 보고 |

## 3. 등급별 대응 절차
### 3.1 1등급
1. 당직자는 감지 즉시 장애 채널에 상황을 공유하고 장애 지휘자(IC)를 지정한다.
2. 10분 이내 경영진·고객 담당에게 1차 보고한다.
3. 복구 우선순위: 데이터 보전 → 서비스 복구 → 원인 분석.
4. 30분 단위로 진행 상황을 보고하고, 복구 후 24시간 이내 RCA(근본 원인 분석) 보고서를 제출한다.

### 3.2 2등급
1. 30분 이내 팀장에게 보고하고 대응 담당자를 지정한다.
2. 우회 경로(대체 AZ, 리플리카 승격)를 우선 적용한다.
3. 복구 후 3영업일 이내 RCA 를 제출한다.

### 3.3 3등급
1. 2시간 이내 팀 채널에 공유하고 티켓을 등록한다.
2. 정규 근무 시간 내 조치하며, 재발 시 2등급으로 상향한다.

### 3.4 4등급
1. 익일 일일 점검 회의에서 보고한다.
2. 임계치 조정 또는 용량 증설 계획을 수립한다.

## 4. 보고 체계
- 1차 보고: 당직자 → 팀장 (전화 + 장애 채널)
- 2차 보고: 팀장 → 운영본부장 (1·2등급만)
- 대외 공지: 고객 담당이 승인된 문안으로만 발송한다.

## 5. 복구 후 조치
- 모니터링 경보 규칙 보완
- 재발 방지 대책의 Jira 등록 및 기한 관리
- 매뉴얼 개정 필요 시 문서관리자에게 개정 요청
